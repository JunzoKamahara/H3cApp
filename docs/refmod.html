RefMod（保存した参照）を使う

H3cApp v0.7.7から、参照に使う画像・動画・音声を一度だけ符号化して、小さなファイル（.safetensors）に保存できます。これをRefModと呼びます。保存したRefModはどの生成にも参照として入れられ、毎回符号化し直すことはありません。プロンプトに <Picture 1> のような番号を書く必要もありません。

RefModとふつうの参照の違い

ふつうの参照（「参照画像・動画・音声」に入れたファイル）は、生成のたびに2つの処理を受けます。

  1. 映像・音声のVAEで符号化して、動画を描く本体（DiT）に参照として渡します。
  2. 画像と動画は文章の部分（テキストエンコーダー）にも見せて、プロンプトの <Picture 1> や <Video 1> がどの参照を指すかを分からせます。

RefModは、1の結果をファイルに保存したものです。生成では1を省き、保存した中身をそのままDiTに渡します。2は行いません。

ふつうの参照RefMod
生成のたびの符号化するしない（保存した中身を読むだけ）
文章の部分に見せる見せる（<Picture n> などの番号が付く）見せない（番号は付かない）
ファイル元の画像・動画・音声.safetensors（数KB〜数百KB）
中身を小さくするできない「圧縮」で作ればできる

文章の部分に見せないので、RefModは「この人物」「この物」をプロンプトの番号で指す使い方には向きません。参照の見た目や雰囲気を、プロンプトの言葉と合わせて生成に効かせる使い方になります。

必要なもの

  • Ref2VAのモデル：RefModを作るのにも使うのにも、参照を使う生成と同じRef2VAが必要です。入っていなければ、「モデル管理」でそのモデルの「…」→「Ref2VAを追加…」で加えます（はじめ方）。
  • M5の高速モードで生成するときは、ふつうの参照と同じく参照画像用のint8キャッシュを使います。

RefModを作る

  1. 参照に元のファイルを入れます。入力パネルで「画像から」を選び、「参照画像・動画・音声」にします。「ファイルを選ぶ…」で、元にする画像・動画・音声を追加します。
  2. その行の「RefModとして保存…」を押します。
  3. 名前とモードを決めて「作成」を押します。項目は下の表のとおりです。ふつうは名前だけ決めれば十分です。

作ったRefModは、RefModフォルダ（~/Library/Application Support/H3cApp/RefMods/）に保存され、「モデル管理」の「RefMod」に並びます。「作成したRefModを参照に追加する」がオン（初期値）なら、参照の一覧にも加わります。元のファイルの行は残るので、要らなければ「取り除く」で外します。

作成は生成と同じGPUの処理です。生成中に押すと、その生成が終わってから始まります。シートの「中止」で止められます。

シートの項目

項目初期値意味
名前ファイル名一覧に出る名前で、ファイル名にもなります
モードFull（そのまま）「Full（そのまま）」か「圧縮（小さい格子に）」。音声はFullだけです
解像度の上限1024 px短い辺がこれより大きい画像・動画は、縮めてから符号化します。拡大はしません（短い辺が320 px未満なら320 pxまで広げます）
使うコマ数16動画だけ。動画全体から均等に選ぶコマ数で、5、22、39…に切り下げます（16なら5コマ）。5コマ未満の動画は先頭の1コマだけ使います
格子の長辺16圧縮だけ。長い辺をこの数のマスにまとめます。小さいほどトークンも細部も減ります
調整ステップ500圧縮だけ。まとめた格子を元の符号化に近づける回数です。0は平均のままです
最大秒数15音声だけ。先頭からこの秒数までを使います

Fullと圧縮

  • Full：符号化した中身をそのまま保存します。同じ大きさで符号化したふつうの参照と、中身が一致します。
  • 圧縮：符号化した中身を小さな格子に平均してから、元に近づくよう調整して保存します。参照のトークンが減るので、生成の計算が軽くなります。そのかわり、細部や動きは失われます。人物の顔や体を覚えさせる仕組みではありません。

Apple M5・24GBで、768×512の画像と3秒の音声から作った例です。時間はVAEの読み込みを含む1回目の値です。

作ったもの参照のトークンファイル作成時間
画像・Full38474 KB6秒
画像・圧縮（長辺16、500ステップ）408 KB4秒
音声3秒24016 KB2秒

同じ画像を「横長・小」の生成でふつうの参照にすると117トークンでした。ふつうの参照は出力の大きさに合わせて縮められますが、RefModは作ったときの大きさのまま使われます。そのため、FullのRefModはふつうの参照よりトークンが多くなることがあります。軽くしたいときは、解像度の上限を下げて作るか、圧縮で作ります。

生成に使う

  1. 参照の欄を開きます。「画像から」→「参照画像・動画・音声」にします。
  2. 「RefModを追加…」を押し、メニューからRefModを選びます。一覧にないファイルは、メニューの「ファイルを選ぶ…」で選べます。
  3. 必要なら、ふつうの参照と組み合わせます。順番は一覧の順です。
  4. プロンプトを書いて生成します。

RefModの行には、名前、中身（種類・大きさ・トークン数・Fullか圧縮か）と、強さのスライダーが出ます。一覧の下の「参照で増えるトークン」と「必要なメモリの目安」には、RefModの分も含まれます。

強さ

強さは0.05〜1で、初期値は1です。1では保存した中身をそのまま使います。1より小さくすると、中身をぼかした自分自身と混ぜるので、値が小さいほど参照の細部が消え、効きが弱まります。

「再現度を何%にする」という重みではなく、ぼかしの量です。0.3まで下げると、参照の形や色は残りますが、細部はかなりぼやけます。計算はComfyUI-MiniMaxH3ModのApplyノードと同じです。

バンドル

複数のRefModを1つにまとめたファイル（バンドル）を選ぶと、「バンドルの中身を選ぶ」が開きます。使う中身にチェックを付けて「追加」を押すと、中身ごとに1行ずつ参照に加わります。強さは行ごとに変えられます。

音声のRefMod

音声から作ったRefModも使えます。ふつうの音声の参照と違い、プロンプトに <Audio 1> は付きません。ふつうの音声の参照は画像か動画の参照と組み合わせる必要がありますが、音声のRefModは単独でも使えます。

プロンプトの書き方

RefModには <Picture n> などの番号が付きません。番号はふつうの参照だけに、種類ごとに1から振られます。たとえば「画像、RefMod、画像」の順なら、2枚の画像が <Picture 1> と <Picture 2> になります。RefModの中身は「赤いボールが…」のように言葉で書きます。

モデル管理で管理する

ツールバーの「モデル管理」を開き、「RefMod」を選ぶと一覧が出ます。

  • 各行に、名前、ファイルの場所、中身（バンドルなら中身ごと）が出ます。
  • 行の「…」メニューで、「名前を変更」「Finderで表示」「ファイルをゴミ箱に入れて削除」ができます。RefModフォルダの外にあるファイルは「一覧から外す」になり、ファイルは消しません。
  • 「フォルダを開く」で、RefModフォルダをFinderで開きます。ここに入れた.safetensorsは、次にこの画面を開いたときに一覧に載ります。
  • 「追加…」で選んだファイルは、RefModフォルダにコピーしてから一覧に加えます。
  • ドラッグで並べ替えられます。「RefModを追加…」のメニューもこの順になります。

ComfyUIなどで作ったRefModを使う

形式は、ComfyUIのノード集ComfyUI-MiniMaxH3ModのRefModと同じです。その「Extract H3 RefMod」で作ったファイルや、配布されているRefModは、変換せずにそのまま使えます。H3cAppで作ったRefModも、ComfyUIで読めます。「モデル管理」の「RefMod」の「追加…」で取り込むか、RefModフォルダに入れます。

  • 読める形式：中身が1つのファイル（形式2〜4）と、バンドル（形式5）。画像・動画・音声のどれも使えます。
  • 使えないファイル：中身が壊れている、形が合わない（画像なのに2コマあるなど）ファイルは、一覧に理由が出て、生成には使えません。
  • 作れる形式：H3cAppが作るのは形式4の単体のファイルです。バンドルは作れません。

配布されているRefModには、それぞれの配布元のライセンスや説明があります。使う前に確認してください。実在の人物をもとにしたRefModを使うときは、肖像や名誉の扱いにも注意してください。

プロジェクト・続き・つなげて生成

  • プロジェクト：プロジェクトを開いて生成すると、使ったRefModのファイルも、ほかの参照と同じくプロジェクトにコピーされます。強さとバンドルの中身も記録され、「設定を戻す」で元どおりになります。元のRefModを消しても、プロジェクトの動画の設定は壊れません。
  • 動画の続き・つなげて生成：RefModも、ふつうの参照と同じく引き継がれます。
  • カスタムクリップ：「同じ参照画像を使う」を外したクリップの参照にも、「RefModを追加…」でRefModを入れられます。パネルと同じく行ごとに強さを変えられ、バンドルは中身を選んで加えます。

上限と注意

  • 参照の上限（画像9、動画3、音声3、合わせて12）に、RefModも中身の種類で数えます。参照の音声は、RefModの分も含めて合わせて15秒までです。
  • 動画のRefModは、作るときに選んだコマ（初期値で5コマ）だけを持ちます。長い動画の動き全体を覚えているわけではありません。
  • 圧縮すると細部と動きが失われます。人物の顔をはっきり残したいときはFullで作ります。
  • RefModは保存したときの中身のままです。元の画像を直したら、作り直します。
  • 複数の人物を番号で描き分けたいときは、番号の付くふつうの参照を使います。
  • ComfyUI-MiniMaxH3Modにある次の機能はありません：同じRefModを何回も重ねる機能、ステップごとに強さを変える曲線、RefModを画像に戻して文章の部分に見せる実験的な経路、複数の元を1つのRefModに重ねる・混ぜる・マスクする機能、バンドルの作成。

ローカルAPIからも、RefModの一覧・作成と、RefModを使う生成ができます。手順は、GitHubのREFMOD.ja.mdにあります。
