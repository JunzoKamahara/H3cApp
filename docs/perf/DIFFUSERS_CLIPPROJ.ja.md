# P3：動画用の軽量テキストエンコーダ（Qwen3-VL-4B＋ClipProj）の実装と検証

測定日：2026年11月18日  
対象：`DIFFUSERS_H3_ADOPTION_PLAN.ja.md` 第4節「P3：動画用Qwen3-VL-4B＋ClipProj」  
ブランチ：`diffusers-p0`（未コミット）

H3の動画モデルは、Qwen3-VL-32Bの先頭50層の出力（5,120幅）をテキスト条件として読む。ClipProjは、小さいQwen3-VL-4Bの途中の層の出力（2,560幅）を、行列1つでこの5,120幅へ写す投影である。32Bを4Bに置き換えられれば、テキストエンコーダの容量とメモリが減る。

ここでは、この方式を診断用の設定としてエンジンに実装し、参照実装との一致、32Bとの差、生成結果、メモリと時間を確かめた。既定は32Bのままで、アプリの画面とプリセットは変えていない。

## 1. 結論

1. **実装は参照実装と一致した。** 同じ4B・同じ投影・同じトークン列で、エンジンの出力とPyTorch（F32で計算）の出力の差は、行ごとの相対差で中央値0.65〜0.71%、コサイン類似度は0.9996以上だった。PyTorchをBF16で計算した結果とF32の結果の差（中央値0.68〜0.80%）と同じ大きさで、残っている差はBF16の演算の丸めである。

2. **テキストエンコーダ段階のメモリは4.75 GiBから1.60 GiBに、時間は6〜10秒から0.8〜0.9秒になった。** 512×512・5秒では、プロセス全体のピークも4.75 GiBから3.8〜4.4 GiBに下がった（ピークの段階がテキストエンコーダから映像VAEの読み込みに移る）。長い動画ではピークがDiTにあるので、変わらない。生成全体の時間は変わらない（約10分のうち数秒）。

3. **生成される映像は、32Bのときとは別のものになる。** 同じseedでも構図や色が変わり、32Bの出力とのPSNRは12〜18 dBだった。画質が悪いという意味ではなく、条件が変わって生成の軌道が分かれるためである。

4. **英語のpromptは、6本とも内容に沿った映像になった。** 短い文、情景の描写、116トークンの長い描写（陶芸の工房）のいずれも、主な指示（被写体、場所、棚の3つの器の色と並び、右隅の黒猫、カメラの動き）は再現された。ずれたのは、promptにない傘が加わる（雨の街）、「青いエプロン」が「青いシャツと灰色のエプロン」になる（工房）といった細部である。

5. **日本語のprompt（1本）は、32Bより指示から離れた。** 「カメラは後ろから追いかける」に対して正面からの顔の寄りになり、promptにない発話の口の動きが出た。32Bの出力は横後ろからで、指示に近い。1本だけの結果である。

6. **台詞タグ（`<d>`…`</d>`）は使えない。** 4Bの語彙にないため、promptにタグがあれば理由を表示して生成を断る。H3の特徴である発話の指定ができないことが、この方式のいちばん大きい制約である。

7. **4Bの量子化による差は、32Bを4Bに置き換える差よりずっと小さい。** int8の4BとBF16の4Bでは、テキスト条件の差は中央値1.2〜1.6%、生成結果は同じ構図で色が少し変わる程度（PSNR 20.3 dB）だった。4Bと32Bのテキスト条件は、コサイン類似度の中央値で0.81〜0.95である。

8. **既存のP-H3-Image用の4Bは、代わりに使わないほうがよい。** P-H3-Imageの4Bは配布元が追加学習した重みで、投影を作ったときの4Bとは別物である。動きはするが、同じ投影・同じseedで、標準の4Bとは別の構図になった（PSNR 12.5 dB）。計画書の「既存の4B実行基盤を利用」は、実行するコードには当てはまるが、重みには当てはまらない。

9. **ディスクの節約は、まだ実現していない。** 32Bのテキストエンコーダ（このMacでは18.2 GB）を、4B（int8で4.86 GB、使うのは先頭24層の2.81 GB）と投影（26 MB）に置き換えられる計算だが、モデルの読み込みは今も32Bがあることを前提にしている。32Bなしの構成を扱うには、モデルの登録・取り込み・メモリ計画の変更が要る（計画書のP5の範囲）。

10. **既存の経路は変わっていない。** 32Bの動画用テキスト条件と、P-H3-Image（BF16とint8）のテキスト条件は、変更の前後でバイト単位で一致した。`make test`は全て通った。

## 3. 実装

設定は環境変数2つで、両方を指定したときだけ働く。

| 設定 | 内容 |
|---|---|
| `H3_TEXT_PROJECTION` | 投影のファイル（safetensors） |
| `H3_TEXT_PROJECTION_ENCODER` | 投影の元になったQwen3-VLのフォルダ（`model.safetensors`を置く） |

- **方式の識別：** 投影は、指定されたファイルがあるときだけ使う。ファイル名や幅から推測しない。P-H3-Imageのconnector（`text_connector.*`、5か所の特徴を連結）とは別の経路で、connectorのコードには手を入れていない。
- **途中の層まで実行：** `tap`=24なら、4Bの先頭24層だけを読んで実行する。25層目以降と最終の正規化は読まない。
- **投影：** F32で「標準化 → 行列を掛ける → 元の尺度に戻す」を行い、最後にBF16へ丸める。F16のファイルはF32に広げて読む。
- **先頭行：** シーケンスの先頭行だけを`sink_out`に置き換える。
- **キャッシュ：** 条件のキャッシュの鍵に、投影のファイル（パス、大きさ、更新時刻）と4Bのフォルダを入れた。投影や4Bを替えると、古い条件は使われない。
- **対象：** 文章だけからの生成（T2V）に限る。

変更したファイル：

| ファイル | 内容 |
|---|---|
| `src/model/h3_text_projection.c`・`.h`（新規） | 投影の読み込み、検査、適用 |
| `src/model/h3_text_encoder.c`・`.h` | `h3_text_encode_projected_bf16`。途中の層で止めて投影する |
| `src/core/h3.c` | 設定の読み取り、対象外の条件の拒否、T2Vの経路での呼び出し |
| `src/core/h3_conditioning.c` | キャッシュの鍵 |
| `src/core/h3_options.c` | 設定2つの登録 |
| `tests/test_h3.c`・`tests/test_frame_latent.c` | 投影の計算と拒否条件、キャッシュの鍵 |
| `tests/text_projection_embed.c`（新規） | 1つのpromptのテキスト条件を書き出す道具 |
| `tools/perf/ref_text_projection.py`（新規） | PyTorchでの参照計算 |

## 4. 参照実装との照合

同じトークン列（エンジンが出したID）を、transformersのQwen3-VLと`qwen3vl_4b_bf16.safetensors`で計算し、同じ式で投影した結果と比べた。値は行ごとの相対差（差のL2ノルム÷参照のL2ノルム）で、先頭行は別に見た。投影はv3.1。

| prompt | トークン数 | エンジン（BF16）とF32の参照 | PyTorch（BF16）とF32の参照 | エンジン（BF16）とPyTorch（BF16） |
|---|---|---|---|---|
| 猫と毛糸玉（英語） | 9 | 中央値0.70%、最大0.94% | 0.80%、1.06% | 0.98%、1.72% |
| 雨のネオン街（英語） | 20 | 0.67%、0.89% | 0.68%、1.18% | 0.81%、1.57% |
| 雨上がりの路地（日本語） | 29 | 0.71%、1.22% | 0.73%、1.06% | 0.95%、1.60% |
| 陶芸の工房（英語、長文） | 116 | 0.65%、3.23% | 0.68%、2.08% | 0.87%、5.07% |

- **エンジンは、PyTorchのBF16と同じ程度にF32の結果に近い。** 残っている差は、24層をBF16で計算するときの丸めで、実装の違いではない。コサイン類似度の最小は0.9996（長文の1行）。
- 先頭行（`sink_out`）は、4本ともビット単位で一致した。
- トークンIDは、4本ともtransformersのトークナイザーの結果と同じだった。
- 初版の投影でも同じ傾向だった（エンジンとPyTorchのBF16の差は、中央値0.74〜0.98%、最大4.58%）。
- 投影は誤差を大きくしない（途中の層の出力で0.6%の差が、投影後は約0.5%）。
- 参考：PyTorchのBF16の計算は、同じ手順なら繰り返しても同じ結果になるが、25層目以降を外して計算したときと全36層を載せて計算したときでは0.8%違った（数学的には同じ計算）。原因は調べていない。BF16の計算にこの程度の幅があることの傍証として記す。

合成の小さい投影（3→5,120）での厳密な検査は`make test`に入れた（F32とF16、行列の向き、先頭行、丸め）。

## 5. 4Bの量子化による差

エンジンで、int8の4BとBF16の4Bを比べた。

| 比較 | 結果 |
|---|---|
| テキスト条件（int8とBF16、4本、2種の投影） | 行ごとの相対差は中央値1.2〜1.6%、最大1.8〜2.6%（長文の1行だけ4.1〜5.9%）。コサイン類似度の最小は0.9983 |
| テキスト条件（int8とF32の参照） | 中央値1.33〜1.61%、最大1.88〜2.07%（長文の1行だけ6.8%） |
| 生成結果（猫と毛糸玉、v3.1、int8とBF16） | PSNR 20.3 dB、SSIM 0.686、映像latentの相対差0.35、音声latentの相対差0.06。同じ猫・同じ構図で、毛糸玉の色が茶色と緑に分かれた |

int8とBF16のどちらを使っても、32Bの出力との距離は同じだった（PSNR 14.69 dBと14.74 dB）。

## 8. メモリ・時間・容量

512×512・5秒・20ステップ。メモリはプロセスのフットプリントの最大値。

| 項目 | 32B | 4B int8＋投影 | 4B BF16＋投影 |
|---|---|---|---|
| テキストエンコーダ段階のピーク | 4.75〜4.78 GiB | 1.60〜1.63 GiB | 1.44 GiB |
| テキストエンコーダの時間 | 6.1〜10.2秒 | 0.81〜0.88秒 | 0.91秒 |
| プロセス全体のピーク | 4.75〜4.78 GiB（テキストエンコーダ） | 3.8〜4.4 GiB（映像VAEの読み込み） | 4.40 GiB |
| テキスト側のファイル | 18.2 GB | 4.86 GB（使うのは2.81 GB）＋26 MB | 8.88 GB（使うのは5.62 GB）＋26 MB |

- 生成全体の時間は変わらない。同じ日に続けて実行した組で、日本語が646秒と617秒、長文が632秒と626秒だった（テキストエンコーダの差は約5秒で、残りは実行ごとのばらつき）。
- DiTのピークは、トークン数で決まり、テキストエンコーダの種類では変わらない。長い動画で生成できる範囲は広がらない。
- メモリ計画（`h3_plan.c`）は、投影を使うときも32Bのテキストエンコーダ段階を見積もっている。実際より大きい側なので安全だが、正確ではない。

## 9. 断る条件

どれも、理由を表示して生成を始めない。

| 条件 | 表示 | 確かめ方 |
|---|---|---|
| `H3_TEXT_PROJECTION_ENCODER`がない | 投影の元になったQwen3-VLのフォルダが要る | 生成の実行 |
| promptに`<d>`または`</d>`がある | 台詞タグは使えない。タグを外すか、H3のテキストエンコーダを使う | 生成の実行 |
| 最初・最後のフレーム、参照、音声の指定、続きの生成、初期latentのいずれかがある | 文章だけからの生成に限る | 生成の実行（5通り） |
| 投影のメタデータに`tap`がない、整数でない、1〜64の外 | `tap`がない（または値）と表示 | 生成の実行（`tap`なし）と`make test` |
| `tap`が4Bの層数以上（36層の4Bに`tap`=36） | 投影が読む層と、テキストエンコーダの層数 | 生成の実行 |
| 投影の幅とテキストエンコーダの幅が違う（4B用の投影に32Bのフォルダ） | 投影は幅2,560用、このテキストエンコーダは幅5,120 | 生成の実行 |
| `-mlp`のファイル | 対応していない。行列だけのファイルを使う | `make test`（合成のファイル） |
| `W`の向きが逆、`sink_out`がない、`std_in`に0以下の値、非有限の値 | それぞれの内容 | `make test`（非有限の値はコードのみ） |
| トークンIDが151669以上（4Bの語彙の外） | H3固有のタグのIDである | コードのみ。現在のトークナイザーはこのIDを出さない（11節の末尾） |

## 10. 既存の経路の回帰確認

- 変更前（commit `9955561`）と変更後で、次の3つのテキスト条件がバイト単位で一致した：P-H3-ImageのBF16、P-H3-Imageのint8、動画用の32B。
- `make test`（`CCV_DIR`を指定）は全て通った。`tests/test_h3.c`は406,742件、設定の検査は168件。
- 設定を指定しない32Bでの生成が、再ビルド後も動くことを確かめた（512×512、2ステップ）。変更前の生成結果とのバイト単位の比較は、テキスト条件の一致で代えた。

## 11. 限界

- **アプリからは使えない。** 環境変数での診断だけである。モデルの登録、取り込み、画面、生成の記録（メタデータ）には手を入れていない。
- **32Bがないと動かない。** モデルの読み込みが32Bのテキストエンコーダを必須にしている。ディスクとダウンロードの節約は、この前提を外す変更の後に初めて得られる。
- **T2Vだけ。** 最初のフレーム、参照（Ref2VA）、RefMod、音声の指定、続きの生成は断る。配布元も参照との併用は未検証としている。
- **台詞タグが使えない。** 発話を指定するpromptは32Bが必要になる。
- **確かめた本数が少ない。** prompt 5種（英語4、日本語1）、各1 seed、512×512・5秒・20ステップだけである。日本語の結果は1本で、傾向とは言えない。LoRA（4・8ステップ）、token reduction、core reuseとの組み合わせ、ほかの解像度は実行していない。
- **目視は一覧画像だけ。** 動きと音声は確かめていない。
- **32Bの量子化の違いを分けていない。** 投影はnvfp4の32Bに合わせて作られ、このMacの32BはGGUFである。
- **`-mlp`の投影は未対応。** 配布元は、行列だけの版より当てはまりがよいとしている。
- **4Bのファイルは、使わない後半12層も含む。** 先頭24層だけに切り詰めたファイルを作る道具は作っていない。
- **キャッシュの鍵は、単体テストで確かめた。** アプリで投影を切り替えながら続けて生成する確認はしていない。

なお、検証の途中で、P3とは別の事実が見つかった。H3cAppのトークナイザーは、H3固有のタグ（`<d>`、`</d>`など7個、ID 151669〜151675）を特殊トークンとして読んでおらず、32Bの経路でも普通の文字列として分割している（「He says `<d>`Hello`</d>`」が、参照実装では6トークン、H3cAppでは8トークンになる）。これは現行の32Bの経路の挙動で、今回は変えていない。

## 12. 判断の材料

| 観点 | 内容 |
|---|---|
| 得られるもの | テキスト側のファイルが18.2 GBから約2.8〜4.9 GBになる（読み込みの変更が前提）。テキストエンコーダ段階のメモリが約3.1 GiB減る |
| 得られないもの | 生成の時間（変わらない）、長い動画で生成できる範囲（変わらない） |
| 失うもの | 32Bと同じ絵（別の絵になる）。台詞タグ。T2V以外のモード（現状） |
| 残る作業 | 32Bなしのモデル構成（登録・取り込み・メモリ計画）、画面、生成の記録、4Bの配布形態（再配布の条件の確認を含む）、ほかのモードの個別の検証 |

- メモリの面では、効果が出るのは短い動画でテキストエンコーダがピークになる場合だけで、その値（4.75 GiB）は16GBのMacでも問題にならない。
- したがって、製品に入れる理由になりうるのは、ダウンロードとディスクの容量である。
- 診断の設定として残しておく分には、既定の経路に影響がない（設定しなければ何も変わらない）。

## 13. 再現手順

ファイルは`~/H3cApp-models/ClipProj/`にある（`dl/`に取得した4つ、`4b_int8/`と`4b_bf16/`に`model.safetensors`という名前のリンク、`out/`に生成結果と一覧画像、`cmp/`にテキスト条件）。

生成：

```bash
P0_OUT=~/H3cApp-models/ClipProj/out P0_SEED=7 tools/perf/p0_run.sh p1_v31_int8 512 512 124 20 H3_TEXT_PROJECTION=$HOME/H3cApp-models/ClipProj/dl/mmh3-4b-ClipProj-v3.1.safetensors H3_TEXT_PROJECTION_ENCODER=$HOME/H3cApp-models/ClipProj/4b_int8
```

テキスト条件の書き出しと、参照との照合（`ref_4b/`は、4Bの`config.json`と`qwen3vl_4b_bf16.safetensors`を`model.safetensors`として置いたフォルダ）：

```bash
build/bin/h3_text_projection_embed <tokenizer.json> ~/H3cApp-models/ClipProj/4b_bf16 <投影> "<prompt>" engine.safetensors build/bin/h3_shaders.metal
```

```bash
~/H3cApp-models/ph3-venv/bin/python -I tools/perf/ref_text_projection.py ~/H3cApp-models/ClipProj/ref_4b <投影> engine.safetensors reference.safetensors --float32
```

`--float32`の参照計算は、メモリを約17 GB使う。
