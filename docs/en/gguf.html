Using GGUF (quantized) models

From H3cApp v0.6.0 a quantized model (GGUF) can stand in for the official model (about 134 GiB for FL2VA alone, used for generating from text and first images). What you download and store drops to about 45 GB with the recommended files, or about 35 GB at the smallest.

What comes as GGUF and what doesn't

A MiniMax H3 model has several parts. Only the parts with large weights are published as GGUF; the rest come from the official model.

PartWhere it comes fromTypical size
DiT (FL2VA)
from text, first and last images		GGUF21.4 GB at Q8_0, 11.4 GB at Q4_K
DiT (Ref2VA)
from reference images, video, audio		GGUF (optional)about the same as FL2VA
Text encoderGGUF18.2 GB for the H3-specific Q4_K_M, 34.8 GB for Qwen's Q8_0
Vision part (mmproj)GGUF (not needed when the text-encoder file has it)1.2 GB at F16
Tokenizer and configsthe official model (no GGUF)tens of MB
Video and audio VAEsthe official model, or unsloth's safetensors (no GGUF)11 GB official, 5.9 GB unsloth

A tokenizer is a few MB of vocabulary, not weights, so there is no GGUF of it. The VAEs aren't published as GGUF either, but unsloth and Comfy-Org publish them as single safetensors files (the video VAE in FP16, half the size), which H3cApp reads too.

Setting up with the download wizard (recommended)

Check the licenses before downloading. The MiniMax H3 model (the official one and GGUF conversions such as unsloth's) is under the “MiniMax H3 Community License Agreement”, Qwen's text and image parts under the “Apache License 2.0”. See License.

  1. Open the wizard. Use “Set Up the MiniMax-H3 Model”, shown at first launch; Model Manager's “Download and Add…” opens it too.
  2. Choose “GGUF (quantized) and needed parts” under “What to download”.
  3. Pick a file for each part. With the default sources, these are recommended:
    PartRecommendedSmaller
    DiT (FL2VA)unsloth's Q8_0 (21.4 GB, tested)Q4_K (11.4 GB)
    Text encoderunsloth's H3-specific Q4_K_M (18.2 GB, 50 layers, with the image part)—
    VAEsunsloth's VAEs (5.9 GB, tested)—
    For the most certain text-encoder quality, choose Qwen's own Q8_0 (34.8 GB, tested). The import then cuts it to the 50 layers used (about 27 GB written), so that much more space is needed; it has no image part, so the mmproj (F16, 1.2 GB) is added automatically. To generate with reference images, video or audio too, turn on “Include Ref2VA”.
  4. Choose where it goes. The “Location” and “Folder name” become the imported model's folder; the downloads are kept inside it until imported. Even on an external disk, the import clones within that disk, so the space isn't doubled.
  5. Press “Download and Import”. Download, import and registration in Model Manager run on their own. An interrupted download resumes next time.

Before you press it, the wizard shows the download size, what the import will write, and the free space on the destination disk; with too little room (2 GB is kept in reserve) the button stays off.

Changing the source

Each part's source (a Hugging Face repository) can be changed.

  • Known sources: the menu next to the source field offers publishers known to carry that part.
  • Listing: the download-arrow button (or Return in the field) reads the first bytes of every file in the source and lists that part's files by what is inside them, not by their names, so each publisher's naming doesn't matter. What was read is kept, so the next time is instant.
  • Custom: “Custom…” in the menu takes a repository name or a Hugging Face URL: a repository (https://huggingface.co/owner/name), a folder (…/tree/main/vae), one file (…/blob/main/xxx.gguf, …/resolve/main/xxx.gguf), on main or another branch. Custom places stay in that part's menu and can be removed with “Remove Custom”.
  • Remembered: the source chosen is kept per part for next time.

Files the app can't use are still listed, with “(unsupported: reason)”, and can't be picked; see supported formats.

Importing GGUF files you have

With GGUF files already on disk, use Model Manager's “Import GGUF…”.

  1. Choose files. “Add GGUF Files…” adds files; “Add from Folder…” adds a folder's (three levels down). Each file is inspected and shown as a DiT, text encoder or vision part. FL2VA and Ref2VA DiTs have the same tensors, so a file whose name contains ref2va is taken as Ref2VA (you can switch it). Missing parts show where to get them, with a “Download…” button.
  2. Review. The file used for each part and what is missing are shown; with several files for one part, pick one. “Clone parts from” chooses where the tokenizer, VAEs and configs come from: a model in Model Manager, a folder picked with “Register Folder…”, or the official shared parts fetched with “Download Shared Parts…”.
  3. Press “Import”. The model folder is created in ~/Library/Application Support/H3cApp/Imported/ and registered.

After importing

  • Model Manager's info button shows what the model holds (each part's format and size, AdaLN form, layers, caches, the import record) and what it can do.
  • For the fast M5 mode, build the int8 cache (about 19 GB) with “Build Cache…” in Advanced Settings; GGUF models can have one too.
  • M1–M4 run with SSD streaming; GGUF weights are read still quantized and expanded on the GPU, so less is read.

Supported formats

  • Quantization: Q8_0, Q4_0, Q4_1, Q5_0, Q5_1, Q2_K–Q6_K, F16, BF16, F32. Mixes such as unsloth's “UD-…_XL” work when made only of these.
  • Unsupported (listed with the reason): files with IQ types (IQ4_XS, IQ3_XXS, …), I8 and the like; split GGUF files; safetensors DiTs and text encoders (only GGUF can be imported); VAEs in number formats the app can't read (F8, int8, …); text encoders with fewer than 50 layers.
  • AdaLN form: DiT GGUFs come with curve-form AdaLN (ComfyUI's “pruned” form) or dense AdaLN. Both work; dense files are about 8 GB larger.
  • Text encoder: the engine uses the first 50 layers of Qwen3-VL-32B; a 64-layer file is cut to those 50 when imported.

Deleting models and disk space

A GGUF import places files as APFS clones on the same disk, so importing takes almost no space; in exchange, models can share data with each other and with the downloaded originals. Model Manager's “…” → “Delete…” works like this:

  • Even when only unregistering, the model's generation caches (int8 cache and the like) are deleted right away (they can be rebuilt).
  • With “Also delete the model files”, the model folder goes to the Trash after one more confirmation; the space emptying the Trash will free is shown. Data shared with other models or originals stays, as those still use it.
  • Deleting the last model also deletes the downloaded shared parts and GGUF files, and caches no model uses.
